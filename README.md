# hematox_spatial

Разметка тканевых зон **опухоль / строма** на H&E-срезах рака яичника.
Обучающие метки выводятся из аннотированной пространственной транскриптомики
Xenium, вручную контуры зон не рисовались. На применении молекулярные данные
не нужны — на входе только изображение.

Две ветки, обе рабочие:

- **пиксельная** — замороженный UNI даёт токен-сетку 14×14, лёгкий декодер
  разворачивает её в карту классов 112×112. Основной результат.
- **патчевая** — тот же UNI, но патч целиком получает один класс; поверх
  GraphSAGE, добавляющий пространственный контекст. Из неё считается TSP.

Всё считалось на CPU (AMD EPYC 7742, 128 ядер), GPU в проекте не участвовал.

## Данные

Три среза рака яичника Xenium (10x Genomics), аннотированные по типам клеток:
`ovary_prime_he` (FFPE), `ovary2_he` (FF), `ovary3_he` (FF, Xenium V1).
Типы клеток сводятся к опухоли и строме по `config/cell_type_map.yaml`.

Дополнительно: 9 не-яичниковых срезов STHELAR как база для патчевой ветки,
39 срезов TCGA-OV (`.svs`) для проверки переноса на внешнюю когорту.

## Результаты

Пиксельная сегментация, leave-one-slide-out, маски Вороного,
фиксированный бюджет 40 эпох без отбора по отложенному срезу:

| отложенный срез | mIoU | Dice опухоль | Dice строма |
|---|---|---|---|
| ovary_prime_he | 0.471 | 0.647 | 0.635 |
| ovary2_he | 0.501 | 0.734 | 0.594 |
| ovary3_he | 0.205 | 0.535 | 0.086 |

Числа воспроизводятся: `seed 42`, признаки UNI закэшированы.

**Про ovary3.** Строма на нём не восстанавливается ни патчевой моделью, ни
пиксельной, ни при уменьшении патча до 128 px. Это не дефект модели: строма там
представлена рассеянными клетками, определёнными молекулярно, без собственного
морфологического рисунка на H&E. Предел метода, а не реализации.

**Перенос на TCGA-OV.** Карты зон на срезах другой когорты, других пациентов и
других сканеров выглядят осмысленно. Связь TSP с общей выживаемостью на пилоте
из 37 пациенток не выявлена (log-rank p ≈ 0.9; Cox HR 0.75, p = 0.77) — при таком
объёме выборки мощности не хватает.

## Установка

```bash
conda env create -f environment.yml
conda activate hematox
```

UNI лежит в gated-репозитории. Один раз: принять условия на
<https://huggingface.co/MahmoodLab/UNI>, затем

```bash
export HF_TOKEN=hf_xxxxxxxx
```

Если веса уже в `~/.cache/huggingface`, токен не нужен.

## Пайплайн

Целиком — `bash scripts/run_pipeline.sh`. Шаги, где результат уже на диске,
пропускаются. По отдельности:

**1. Выгрузка из Seurat.** Координаты клеток и аннотация в CSV:

```bash
Rscript R/export_seurat.R ovary_prime.rds ovary2.rds ovary3.rds
```

Печатает список всех встреченных `cell_type` — их надо разнести по группам
в `config/cell_type_map.yaml`.

**2. Совмещение с H&E.** Xenium отдаёт координаты в микрометрах, модель работает
в пикселях:

```bash
python align_xenium_he.py \
  --cells data/seurat_csv/ovary_prime_cells.csv \
  --align data/raw/ovary_prime/..._he_imagealignment.csv \
  --he    data/raw/ovary_prime/..._he_image.ome.tif \
  --out   data/seurat_csv/ovary_prime_he_cells.csv
```

Шаг обязательный. Без него метки лягут мимо ткани.

**3. Метки патчей.** Файлы перечисляем явно: без `--cells` скрипт заберёт по
маске и невыровненные CSV тоже, и слайды задвоятся.

```bash
python -m src.data.seurat_labels --cells data/seurat_csv/*_he_cells.csv
```

**4. Маски и признаки** (долго, около часа на срез):

```bash
python -u make_seg_masks_v.py --slide ovary_prime_he \
  --cells data/seurat_csv/ovary_prime_he_cells.csv --he <ome.tif>
python -u seg_extract.py --slide ovary_prime_he --he <ome.tif>
```

**5. Обучение декодера**, отдельно на каждый отложенный срез:

```bash
python -u seg_train.py --val ovary3_he --select fixed --epochs 40 \
  --out outputs/models/seg_fixed_ovary3_he.pth
```

Метрики дописываются в `outputs/results/seg_metrics.csv`.

**6. Применение к новому срезу:**

```bash
python -u seg_infer_svs.py --svs <срез.svs> --model outputs/models/seg_fixed_ovary_prime_he.pth
python -u seg_infer_img.py --he <срез.ome.tif> --model ...
```

На выходе карта зон и доля стромы. По когорте `.svs` — `tcga_tsp.py`.

## Методические решения

**Разбиение по срезам, не по патчам.** Патчи одного среза пространственно
скоррелированы, случайное разбиение по патчам завышает метрики.

**Класс undefined убран.** В первой, трёхклассовой версии он забирал на себя
предсказания: на ovary_prime точность была 0.49. После перехода к двум классам —
0.94. Третий класс остался только в пиксельных масках, где он означает фон.

**Отбор эпохи не по отложенному срезу.** Ранняя остановка по валидации с
последующим измерением на ней же завышает результат: на ovary_prime разница
доходит до 0.20 Dice. Режим `--select fixed` учит фиксированное число эпох и
не заглядывает в отложенный срез. Число эпох при этом само остаётся неподобранным —
это известное ограничение текущей таблицы.

**Метрики — IoU и Dice по классам.** Не accuracy: классы несбалансированы, в
обучающей паре срезов опухоль занимает больше половины размеченных пикселей.

**Веса классов считаются только по обучающим срезам.**

**Маски Вороного лучше дисковых.** Разметка «клетка = диск фиксированного
радиуса» оставляет между клетками неразмеченные промежутки; тесселяция Вороного
заполняет площадь целиком и даёт заметно более высокий Dice.

## Ограничения

Три среза — это пилот. Устойчивой оценки на трёх точках не бывает, разброс между
фолдами велик: Dice стромы от 0.09 до 0.64. Код рассчитан на добавление срезов
одной строкой в списке.

Кодировщик заморожен. Разморозка последних блоков UNI — главный резерв качества,
но на CPU она нереальна.
