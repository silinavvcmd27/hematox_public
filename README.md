# hematox_spatial

Разметка тканевых зон на H&E-срезах рака яичника: **опухоль, гормональная строма,
матриксная строма**. Обучающие метки выводятся из аннотированной пространственной
транскриптомики Xenium, вручную контуры зон не рисовались. На применении
молекулярные данные не нужны, на входе только изображение.

Деление стромы на два типа CAF и есть суть работы: по обычному H&E патолог его не
проводит, а с химиорезистентностью при HGSC связывают именно долю стромы.

Две ветки, обе рабочие:

- **сегментационная** — замороженный UNI даёт токен-сетку 14×14, лёгкий декодер
  разворачивает её в карту классов 112×112. Плотная карта зон и TSR.
- **клеточный граф** — узел это клетка, ребро до 50 мкм. Первый слой делит клетки
  на опухолевые и стромальные, второй разбирает стромальные на подтипы CAF.

Иммунные клетки и сосуды размечены, но в обучении помечены как игнорируемые: они
не распознавались и отбирали ёмкость у остальных классов. Не как фон — класс,
который мы не предсказываем, не должен считаться ошибкой.

Всё считалось на CPU (AMD EPYC 7742, 128 ядер), GPU в проекте не участвовал.

## Данные

Три среза рака яичника Xenium (10x Genomics), аннотированные по типам клеток:
`ovary_prime_he` (FFPE), `ovary2_he` (FF), `ovary3_he` (FF). Типы клеток сводятся
к пяти зонам по `config/cell_type_map.yaml`, обучение идёт на трёх из них.

Дополнительно: два среза яичника из STHELAR как независимая проверка по клеткам,
41 файл TCGA-OV (`.svs`) для переноса на внешнюю когорту, из них два битых и один
дубликат, то есть 38 срезов от 37 пациенток.

**Про `ovary3`.** Его H&E долго был подложен от другого запуска Xenium (V1 вместо
Prime), то есть от физически другого среза того же блока. Отсюда потолок Dice 0.82
при совмещении, который объясняли усадкой ткани. С правильной картинкой
(`Xenium_Prime_Human_Ovary_Cancer_FF`) и поправкой на 2600 px совмещение выходит на
Dice 0.931 при покрытии ткани 0.991. Все прежние числа с участием этого среза
недействительны.

В обучение второго слоя графа `ovary3` не берётся: у него 11 616 гормональных
клеток против 442 матриксных, и он тянет модель в «стромальное значит
гормональное». В первом слое остаётся, там пропорции нормальные.

## Результаты

Сегментация, валидация по слайдам, Dice по пикселям:

| отложенный срез | опухоль | гормональная | матриксная |
|---|---|---|---|
| `ovary2_he` | 0.909 | 0.492 | 0.043 |
| `ovary_prime_he` | 0.921 | 0.399 | 0.406 |

Клеточный граф, слой 1, Dice по отдельным клеткам:

| отложенный срез | опухоль | строма |
|---|---|---|
| `ovary2_he` | 0.893 | 0.844 |
| `ovary_prime_he` | 0.946 | 0.952 |

Слой 2, деление стромы:

| постановка | гормональная | матриксная |
|---|---|---|
| половины одного среза (`ovary2`) | 0.878 | 0.727 |
| `ovary2` → `ovary_prime` | 0.395 | 0.488 |
| `ovary_prime` → `ovary2` | 0.572 | 0.310 |

Внутри среза деление восстанавливается уверенно, между срезами качество падает
вдвое. Ограничение выборочное: пригодных для этой задачи срезов два.

**Внешняя проверка (STHELAR).** Слой 1 на срезах яичника: `ovary_s1` даёт Dice
0.956 по опухоли и 0.928 по строме, `ovary_s0` — 0.597 и 0.508. Разбивка по
однородности тайла объясняет разрыв: на однородных тайлах 0.929 и 0.875, на
смешанных 0.686 и 0.604. STHELAR раздаётся тайлами 256 px при 0.25 мкм/px, то есть
по 64 мкм, а графу нужен контекст около 100 мкм, и на таком тайле он обрезан краями
кадра. Деление стромы на подтипы этим набором проверить нельзя: его разметка
кончается на уровне «фибробласт».

**Перенос на TCGA-OV.** По 14 срезам: TSR медиана 0.308 (размах 0.119–0.540), доля
гормональной внутри стромы медиана 40 % (размах 17–66 %). У единственного пациента
с двумя препаратами (`TCGA-VG-A8LO`) доля гормональной вышла 27.1 % и 26.9 % при
доле стромы 0.403 и 0.140: состав стромы ведёт себя как свойство опухоли, а доля
стромы зависит от того, где прошёл нож. Расчёт когорты продолжается.

## Установка

```bash
conda env create -f environment.yml
conda activate hematox
```

UNI лежит в gated-репозитории. Один раз: принять условия на
<https://huggingface.co/MahmoodLab/UNI>, затем

```bash
export HF_TOKEN=hf_xxxxxxxx
```

Если веса уже в `~/.cache/huggingface`, токен не нужен.

## Пайплайн

**1. Выгрузка из Seurat.** Координаты клеток и аннотация в CSV:

```bash
Rscript R/export_seurat.R ovary_prime.rds ovary2.rds ovary3.rds
```

Печатает список всех встреченных типов, их надо разнести по группам в
`config/cell_type_map.yaml`. Колонка `cell_subtype` обязательна: у части срезов все
фибробласты лежат в `cell_type` одной кучей, и деление CAF живёт только в подтипах.

**2. Совмещение с H&E.** Xenium отдаёт координаты в микрометрах, модель работает
в пикселях:

```bash
python -u check_alignment.py --slide ovary3 --cells data/seurat_csv/ovary3_cells.csv \
  --align data/raw/ovary3/..._he_imagealignment.csv --he data/raw/ovary3/..._he_image.ome.tif
python align_xenium_he.py --cells ... --align ... --he ... --out ... \
  --variant inverse_px --orient xy --shift-x=-2600 --shift-y=-100
```

`check_alignment.py` перебирает варианты матрицы и восемь разворотов кадра,
выбирает по Dice между облаком клеток и маской ткани и печатает готовую команду
пересчёта. Доля клеток на ткани для выбора не годится: сжатое в пятно облако
попадает на ткань почти стопроцентно и выигрывает у правильного варианта.
`nudge_align.py` доводит сдвиг вручную, `zoom_align.py` показывает вырезки в
реальном увеличении, где видно, попали ли точки в ядра.

**3. Маски Вороного:**

```bash
python -u make_seg_masks_v.py --slide ovary3_he --cells <aligned.csv> --he <ome.tif> \
  --patch-size 512 --stride 512
```

Шаг задаётся в пикселях, а пиксель у срезов разный. Для `ovary3` он вдвое мельче,
поэтому 512 против 256 у остальных: так физический шаг у всех одинаковый.

**4. Эталон окраски и признаки** (долго, от получаса до часа на срез):

```bash
python -m src.stain data/raw/ovary_prime/..._he_image.ome.tif data/processed/stain_ref_prime.npz
python -u seg_extract.py --slide ovary_prime_he --he <ome.tif> --max-patches 12000 \
  --stain-ref data/processed/stain_ref_prime.npz
```

Окраска приводится к опорному срезу по Macenko до кодирования: UNI заморожен, и
цветовой сдвиг между срезами уходит прямо в признаки. Матрица красителей
оценивается по срезу целиком, а не по патчу.

**5. Обучение.** Сегментационная ветка:

```bash
python -u seg_train2.py --slides ovary_prime_he ovary2_he ovary3_he --val ovary2_he \
  --classes 1 2 3 --out outputs/models/seg3_val_ov2.pth
```

Графовая ветка:

```bash
python -u cell_graph_build.py --slide ovary3_he --cells <aligned.csv> --he <ome.tif> --patch-size 512
python -u cell_graph_train.py  --train ovary_prime_he ovary3_he --val ovary2_he --out runs/graph/l1.pth
python -u cell_graph_train2.py --train ovary_prime_he --val ovary2_he --caf-only --out runs/graph/l2.pth
```

**6. Применение к новому срезу.** Ключ `--stain-ref` обязателен, если он был при
извлечении признаков, иначе обучение и применение разъедутся по цвету:

```bash
python -u seg_infer_svs.py --svs <срез.svs> --model outputs/models/seg3_deploy.pth \
  --stain-ref data/processed/stain_ref_prime.npz --target-mpp 0.2738 --patch-size 256
python -u seg_infer.py --he <срез.ome.tif> --model ... --stain-ref ...
```

`--target-mpp` задаёт увеличение, на котором училась модель. По умолчанию скрипт
возьмёт родное разрешение файла, и поле зрения окна не совпадёт с обучающим.

**7. Когорта:**

```bash
bash run_tcga.sh 10                       # разметка по одному срезу за раз
python collect_tsr.py                     # TSR и состав стромы в таблицу
python stroma_heterogeneity.py --block-mm 1
python fetch_clinical.py                  # клиника TCGA из открытого API GDC
```

`render_zones.py` перерисовывает карту из сохранённых вероятностей за секунды,
без пересчёта UNI, если нужно подобрать сглаживание или порог мусора.

окраске выбрасывает весь эозин, и считает концентрации по тайлу, а не по срезу.

## Методические решения

**Разбиение по срезам, не по патчам.** Патчи одного среза пространственно
скоррелированы, случайное разбиение по патчам завышает метрики.

**Иммунные клетки и сосуды в NA, а не в фон.** Перевод двух неразличимых классов в
игнорируемые поднял остальные три без единого нового наблюдения: опухоль с 0.849
до 0.909, гормональная строма с 0.363 до 0.492 на одном и том же фолде.

**Нормализация окраски до кодировщика.** UNI заморожен, поэтому исправить
цветовой сдвиг после него нечем. Матрица красителей оценивается по срезу целиком:
на отдельном патче оценка неустойчива и даёт швы между тайлами.

**Отбор эпохи по худшему классу, а не по среднему.** При двух классах модель
норовит схлопнуться и называть один класс для всех клеток. У такой вырожденной
модели средний IoU выше, чем у слабой, но настоящей, и отбор по среднему выбирает
именно её.

**Совмещение проверяется по Dice, а не по доле клеток на ткани.** Односторонний
критерий выигрывает вырожденными преобразованиями, сжимающими облако в пятно
внутри среза.

**Метрики — IoU и Dice по классам.** Не accuracy: классы несбалансированы, в
обучающей паре срезов опухоль занимает больше половины размеченных пикселей.

**Веса классов считаются только по обучающим срезам.**

**Маски Вороного лучше дисковых.** Разметка «клетка = диск фиксированного
радиуса» оставляет между клетками неразмеченные промежутки; тесселяция Вороного
заполняет площадь целиком и даёт заметно более высокий Dice.

## Ограничения

Матриксная строма переносится между срезами несимметрично: при обучении с участием
`ovary2` находится на `ovary_prime` (Dice 0.406), в обратную сторону нет (0.043).
Пригодных для деления стромы срезов два, третий исключён по составу.

Деление стромы не проверено внешне. Независимого набора с разметкой до уровня
подтипа CAF не существует, STHELAR доходит до «фибробласта».

Связь с исходами не проверялась: на тринадцати пациентках это невозможно.
Конвейер готов, вывод возможен после расчёта всей когорты.

Полная когорта TCGA-OV недостижима: видеокарты нет, torch собран без CUDA, срез
считается от получаса до десяти часов. Работа остаётся разведкой на подвыборке,
и причина этому вычислительная, а не методическая.

Кодировщик заморожен. Разморозка последних блоков UNI — главный резерв качества,
но на CPU она нереальна.
